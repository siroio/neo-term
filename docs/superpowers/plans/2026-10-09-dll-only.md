# DLL-only terminal plan

ユーザーの指示: OpenConsoleは残す。仲介EXEは削除し、いかなる経路でも使わない。

- [x] 仲介EXEが存在することとDLL不足時にEXEへ切り替わることを、失敗するテストで確認する。
- [x] 配布EXE、旧比較用EXE、host/classic実装、EXEビルド、LispのEXE起動とfallbackを削除する。
- [x] PowerShellの.NET通知を維持し、cmdの直接パイプ通知とBash標準TCP通知へ移行する。
- [x] 標準ConPTYのclear API不足を明示エラーにし、CLIを維持する。
- [x] CLI仕様を実際のEmacs/DLLを読むテスト経路へ移行する。従来API固有テストを廃止し、出力詰まり時の破棄は既存DLL統合テストで検証する。
- [x] 独立レビューで判明したcmdのCRLF・記号展開・pipe busyを修正する。日本語/&/!を含むパスと5回の連続ファイル要求、実際のEmacs側のcwd通知を確認する。
- [x] 最終ビルド、全CLI・ERT・DLL・GUI検証、配布物の確認。

cmdは改行なしのset /pで送信し、データ取得後の遅延展開でメタ文字の再解釈を避ける。pipeが接続中の場合は回数上限付きで再試行する。Git BashではWindowsの名前付きパイプを直接開けないことを実機テストで確認したため、/dev/tcpから127.0.0.1へ送信する。受信側はセッショントークンを照合し、16KiBと2秒の上限を適用する。外部通知EXEを新設しない。

検証ログ: build/no-helper-red.log、build/no-helper-green.log、build/no-helper-cmd-burst-green.log、build/no-helper-cmd-frontend.log。

最終結果: build/dll-only-build.logのMSVC /W4 /WXビルドとネイティブ契約/VTテストが成功。build/dll-only-final-tests.logでDLL CLI40件、ERT46件、DLL統合20件、byte compile、GUIがすべて成功。日本語と記号のcmd通知、連続送信、標準ConPTYで消去できない場合のCLI維持も検証済み。仲介EXE本体と比較用コピーは削除し、実装内の起動呼出しとビルドルールがないことを確認した。独立レビューも成功。OpenConsole.exeとテスト用CLIは残す。
